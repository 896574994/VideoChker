## 0. 先看这四条（最省时间）

1. **只用 C# 5 语法** —— 如果你还想支持 Windows 7（详见第 1 节）。
2. **`.ps1` 必须 UTF-8 带 BOM；`.bat` 必须纯 ASCII** —— 否则中文会以很隐蔽的方式坏掉（第 3 节）。
3. **改完必须真跑一遍** —— 编译通过 ≠ 功能对（第 6 节）。
4. **同一个事实只留一个源头** —— 写两遍必然漂移（第 5 节，这个项目被咬过很多次）。

## 1. 构建与环境

| 事项 | 做法 | 为什么 |
|---|---|---|
| 编译器 | Windows 自带的 `csc.exe`（.NET Framework 4.x），见 `build.bat` | 不需要 Visual Studio，clone 下来双击就能编 |
| 目标框架 | .NET Framework 4.0 | **Windows 7 上装的就是 4.0**；用更高版本会直接跑不起来 |
| 语言版本 | **C# 5**：不用字符串插值、`?.`、`async/await`、集合初始化器的某些新写法 | `csc.exe`（.NET 4.0 那个）只认到 C# 5 |
| 图标 | 编译加 `/win32icon`，**并且**每个 Form 构造函数里 `SetFormIcon()` | `/win32icon` 只管 exe 文件本身；窗体图标是另一个属性，不设还是系统默认图标 |

### 1.1 两个已知的坑

- **没有 manifest 的副作用**：.NET 4.0 的程序若不带清单文件，`Environment.OSVersion`
  在 Windows 10/11 上会**报成 6.2**（看起来像 Win8）✗ —— 判断系统版本时不要只信它。
- **DPI**：本程序**没有**声明 DPI 感知 ✗，所以在 125% / 150% 缩放的屏幕上，
  Windows 会把整个窗口**位图拉伸**，字会发虚。想修的话：
  加一份 manifest 声明 `dpiAware`，然后逐个窗体调整布局 —— 属于**已知待改进项**（见第 8 节）。

## 2. ffmpeg（最大的那个坑）

**本仓库不包含 ffmpeg 二进制**（体积 + 许可证原因）。请自行下载，放到：

```
bin\ffmpeg\bin\ffmpeg.exe
bin\ffmpeg\bin\ffprobe.exe
```

### 2.1 ★ Windows 7 上必须选"老"构建

- **2024-05-31 之后**的官方构建用到了 Win8/Win10 才有的 API，
  在 Windows 7 上**一启动就崩**：退出码 `0xC0000005`，而且**标准输出、标准错误全是空的** ✗。
- ★ **不要以为是"缺运行库"** ✗ —— 装 KB2999226 / 补 UCRT **没有用**。
  （我们在这个错误方向上浪费过好几轮：真正的原因是那份 exe 的**静态导入**里有
  `api-ms-win-core-synch-l1-2-0.dll`，而 Win7 没有这个 API 集。）
- **怎么确认一份 ffmpeg 能不能在 Win7 上跑**：读它的 **PE 导入表**（DLL 名 + 函数名），
  ★ 不要"在文件里搜函数名字符串" ✗ —— 名字出现在文件里**不等于**程序真的依赖它
  （`GetProcAddress("AddDllDirectory")` 这类动态查表，名字同样留在文件里，
  但程序会自己处理"取不到"）✓ 我们第一版检查就是这么误判好构建的 ✗。
- **唯一的真判据**：在那台 Win7 上跑 `ffmpeg -version`，退出码 0 才算 ✓。
- 老构建的代价：**编解码器版本也老**。对监控录像（H.264 / H.265 + MP4）足够，
  但要新格式就得自己权衡。

### 2.2 其它

- 本程序**不使用** `-hwaccel` ✓ 全部软件解码 —— 所以旧构建缺 `d3d12va` / `amf`
  之类的硬件加速项不影响功能 ✓。
- ffmpeg 出错时会把**完整 URL（含密码）**回显到 stderr ✗ ——
  所以脱敏要放在**日志出口**统一做，逐个调用点去堵是堵不干净的 ✓。

## 3. 编码与脚本（三个真踩过的坑）

| 文件类型 | 要求 | 不遵守会怎样 |
|---|---|---|
| `.ps1` | **UTF-8 with BOM** | PowerShell 5.1 会按系统 GBK 读它 → 中文全乱、`param` 块可能整个失效，**而脚本照样退出 0** ✗✗（最坑的一种：看起来成功了） |
| `.bat` | **纯 ASCII** | cmd.exe 按系统 ANSI 代码页读 → 中文注释会**吞掉后面的命令** |

> ★ 用编辑器/工具改 `.ps1` 时很容易把 BOM 弄掉 ✗ —— 改完记得确认前三个字节是 `EF BB BF` ✓。
> 用脚本生成文件时，显式指定 `New-Object Text.UTF8Encoding($true)` ✓。
>
> ★ 中文注释请写在 `.ps1` / `.md` 里，**不要写在 `.bat` 里** ✓。

## 4. WinForms 的取消（必看）

长任务用 `BackgroundWorker` 时，有两个几乎一定会犯的错：

### 4.1 ★ 先判 `e.Cancelled`，再碰 `e.Result`

```csharp
// ✗ 错的顺序（取消时必崩）
List<Report> reports = e.Result as List<Report>;
if (e.Cancelled) { ... }
```
`AsyncCompletedEventArgs` 在 `Cancelled == true` 时读 `Result`，**必定抛**
`InvalidOperationException: 操作被取消` ✓。

```csharp
// ✓ 对的顺序：取消分支根本不去读 e.Result
if (e.Cancelled) { var partial = _partialReports; ... return; }
var reports = e.Result as List<Report>;
```
部分结果请让 `DoWork` 挂在**一个字段**上（同一个 List 对象，边跑边加）✓。

### 4.2 自己抛的"用户已停止"异常，要在 `DoWork` 里接住

如果底层抛了一个表示"用户主动停止"的异常，而 `DoWork` 没有 catch，
它会被 `BackgroundWorker` 塞进 `e.Error` ✗ → 界面弹出
**「检测过程中发生错误：用户已停止」**（把用户自己的操作当成故障 ✓）。

```csharp
try { ...干活... }
catch (StoppedException) { e.Cancel = true; break; }   // 正常停止 ✓ 不是错误 ✓
```

### 4.3 长任务里"中途停止"是**主路径**，不是边角

本程序检测一个长录像可能要 **20 分钟** ✓ —— 用户几乎不可能在"两个文件之间"的
一瞬间按停止 ✗，他**必然是在文件中途**按 ✓。测试时请专门测这一条。

## 5. 一致性与"两份事实"（被咬过很多次）

> **同一个事实存在两个地方 → 改一处漏一处 → 而且不会有任何报错** ✗

踩过的实例（都是同一类）：

- 安装程序里**写死**了一个日期 → 程序早升级了，安装窗口还显示旧日期 ✗
- 安装程序里**写死**了"解压后约 XXX MB" → 换掉 ffmpeg 之后它就变成假话 ✗
- 发布说明里**写死**了包体积 ✗
- 目录**改名**了，文档里还有 3 处引用指着旧名字 ✗
- **只重打了两个发布包中的一个** → 另一个还停在旧版本，而检查脚本"通过"了 ✗

**对付它的办法不是"下次记得"** ✗，而是：

1. 能算的就算，不要写死（版本号、日期、体积都从**单一源头**取）✓
2. 让**检查脚本去比这两份** ✓（比版本号、比目录是否存在、比文件里有没有写死的日期）

> ### ★ 检查脚本自身的两条纪律
> - **会误报的检查，不该有权挡住发布** ✗ —— 要么把它做准，要么把它降级成"只报告"。
>   一份会冤枉好东西的检查，最后一定会被无视 ✓。
> - **拿一个"已知答案"的输入去试它** ✓ —— 我们的 ffmpeg 兼容性检查就是
>   拿一份**已知能跑**的构建去测，结果它报"会崩" ✗，才发现检查本身是错的 ✓。

## 6. 测试与验证

- **一个"bug 还在的时候也通过"的测试，等于没测** ✗ ——
  写完测试后，把 bug **放回去**跑一遍，看它红不红 ✓（我们靠这一步抓到过两个假通过的测试）。
- 报告类问题的现场信息要**尽可能多**：退出码（**同时给十进制和十六进制** ✓）、
  stdout、stderr、命令行、超时 —— **"输出是空的"也是重要信息** ✓（说明程序还没开口就死了）。
- 提供一个 **「一键导出诊断包」**（环境 + 日志 + 协议报文）✓ ——
  用户只要发**一个文件**，省掉大量来回 ✓。（这就是本项目里"诊断包"的由来 ✓）
- 冒烟测试要**真的启动程序、真的点按钮** ✓。本项目的做法：
  把程序源码和测试代码**一起编译**（`/main:` 指定测试入口），
  然后在**同一个进程里** `new Form()` + 反射调私有方法 ✓ 快且稳 ✓。

## 9. 目录与数据约定

```
AppPaths.BaseDir   =  **exe 所在目录**（★ 不是当前工作目录 ✓ 这一点很关键）
AppPaths.DataDir   =  <exe目录>\data\
```

| 目录 | 内容 |
|---|---|
| `data\` | 设置、流列表（DPAPI 加密）、开屏密码、巡检记录 |
| `logs\` | 运行日志（**出口已脱敏**）、`error.log`（未处理异常） |
| `reports\` | 检测报告 HTML / PDF |
| `archive\` | 归档的视频文件**本身**（最占空间，也最敏感） |

- 程序目录可以**整个拷走** ✓ 数据跟着走 ✓（但 DPAPI 加密的东西换机器/换用户解不开 ✓ 这是设计）。
- 忘了开屏密码：删掉 `data\lock.dat` 即可重置 ✓（本开源版**没有**任何万能密码 ✓）。
